About Enterprise Application Testing (EAT)

How the COE is structured, how it's tracked, and how it helps every engagement.

What EAT is. EAT is a Center of Excellence body, not a project team. It sits above individual ERP/CRM testing engagements and owns the standards, tools, monitoring practices, capability programs and innovation pilots that every engagement draws on. Its output is a living repository: strategy documents, SOPs, templates, trackers and playbooks organized under five pillars, each broken into a discrete, ownable deliverable ("user story") with a named responsibility and clear acceptance criteria.

How it is built. The COE backlog is tracked exactly like a product backlog — 29 deliverables across 5 pillars, each carrying a status (Done / In Progress / To Do / Backlog), an owner role, and the artifacts that satisfy it. That backlog is the single source of truth behind the readiness dashboard — the only place story-level progress is shown — and behind the folder structure of this site.

How it helps. A new ERP or CRM testing engagement should not have to write a test strategy, build a defect log template, or figure out a governance cadence from scratch. It opens the relevant pillar page here, finds the linked SharePoint document, and adapts it — saving ramp-up time and keeping quality practices consistent across programs.

Where documents live. This site never stores document files. Every document is a catalog entry that links out to the team's SharePoint/Teams library. "Registering" a document here just adds it to the catalog with a name, tags and a link — the file itself always stays in SharePoint.

How this repository is organized

Five pillars → each pillar's numbered sub-areas (e.g. 1.1, 1.2 …) → each sub-area's page carries its purpose, owner, acceptance criteria and the linked SharePoint documents for that deliverable. The same five pillars, in the same order, are used across the tracker, the folder structure, and this site — so a reference like "1.4" means the same thing everywhere.

Roles

Viewer — browse pillars and stories, search all content, view and open linked documents.

Contributor — everything a Viewer can do, plus: register documents, edit tags/labels, and update story status on the Dashboard. Switch roles any time using the selector in the top-right of the header — it's a lightweight, no-signup toggle for internal use, not enforced security.
